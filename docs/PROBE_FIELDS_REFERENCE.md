# 屏幕探针上板及读数指南

发布的 bit/SHA256 以 `RELEASE.json` 及 `program/` 为准。引脚及电机设置沿用[原整机完整按键指南](FULL_KEY_GUIDE_REFERENCE.md)。

1. SW2、SW3关闭，下载新bit；等待驱动上电完成，两旗帜置于可复现机械初始位置。
2. 用原图像模式按键进入MOTION界面；KEY1仍是原图像/编辑键，不是独立诊断版的复位键。
3. 打开SW2，等约1秒；SW3从关拨到开。观察原CAN/ERR及其下方橙色C0～C3四行。
4. 出现CAN6 ERR1后拍下整个右上区域，四行完整都要保留。不必手动解码，也不需要示波器或CAN分析仪能收帧。
5. 首个失败事务会冻结四行；后续STOP/DISABLE不会覆盖。关闭SW2后仍保留，重新打开SW2会清除旧快照并开始新一轮记录。系统复位/重下载/断电会清除。

快照在MOTION界面显示；仅字形区域叠加，不改变检测输入。颜色易失编辑、FILL、比赛、归位及回放按原指南操作。本版不增加0x7E0/0x7E1报文。

## 四行定义

所有值为十六进制，每行8位。

| 行 | 8位从左到右 | 含义 |
| --- | --- | --- |
| C0 | MM CC B0 B1 | CAN核实际MODE、CDR、BTR0、BTR1 |
| C1 | SS RR AA FF | 实际状态SR、最近一次WB读取SR、电机地址、功能字 |
| C2 | WW HH NN DD | 失败前最后等待阶段、主机阶段/标志、TX接受数、接口TX完成数 |
| C3 | EE FL EV D1 | TXD边沿数、标志位、事件类别、固定版本标记D1 |

正常工作参考：MODE通常00、CDR80、BTR0=04、BTR1=2A，地址01/02。SR随总线状态变化，不固定为某个字节。BTR04/2A配合实际75MHz为500kbit/s；屏幕只是实际寄存器观察，未测量外部位宽。

WW：01等发送接受、02等接口发送完成、03位置分片间隔、04等匹配应用应答；00尚无等待阶段。快照会记住完成前的等待阶段，不把FINISH/IDLE误记为等待阶段。

HH按位：bit7发送pending，bit6接口fault，bit5..3 WB状态，bit2..0主机phase。phase：0初始化、1轮询SR、2装载TX、3发TX命令、4读RX头、5读RX数据、6释放RX、7中止。WB状态：0SELECT、1ACCESS、2GAP、3DISPATCH、4FAULT。

NN/DD/EE在FF饱和，不回绕；EE是FPGA内部TXD采样边沿，不能当成完整帧计数。DD沿用原接口定义，前轮已证明存在假完成分支，不能只凭DD认定外部已经发帧。

FL位7..0分别为：CAN ready、CAN fault、协议复位已释放、当前TXD、当前同步RXD、曾见TXD低、曾见同步RXD低、曾采到协议复位从释放变为有效。最后一位只检测75MHz采样看得到的变化，0不能排除更窄毛刺。

EV：00运行观察、01首个失败已冻结、02控制器CAN3就绪。未发生失败时数值随运行更新，显示端在帧边界整组捕获；失败后保持原首错记录，不被停止命令覆盖。

## 判断例子

- MODE仍01而EV01：核未退出复位模式候选，不能仅靠CAN ready判断初始化成功。
- NN非零/DD非零但EE00且FL未见TX低：接受/完成标志未对应实际内部发送，检查核配置和CMD写入。
- WW01且NN00：命令未得到发送接受，进一步看SS/RR和HH。
- EE非零且曾见TX/RX低：内部已有总线活动，转向位时序/帧内容/物理接口定位，不能再称内部完全没发。

这些是定位分支，不是预设实板根因。本包不含自动烧录流程；完整整机上板结果需自行记录。
